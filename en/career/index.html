AI-Native Engineering · AI Coding Delivery Workflow

I treat AI coding not as one-shot code generation, but as an engineering delivery pipeline governed by explicit contracts, scoped context, and automated acceptance gates. Engineers own problem framing, architectural constraints, task decomposition, and final verification; coding agents accelerate implementation and test coverage inside those guardrails.

Delivery Stage Engineering Practices & Quality Gates
Requirements Clarify user pain points, backward-compatibility constraints, explicit non-goals, and testable acceptance criteria before coding
Technical Design Define schemas, API contracts, task state machines, data-preserving migrations (PRESERVE_EXISTING_DATA), and backup-format sync points up front
Context Management Encode architecture rules, module boundaries, i18n parity, and import/export checklists in repository-level AGENTS.md to curb agent drift
Task Decomposition Split work into atomic, verifiable increments across data contract → provider/business logic → UI → automated tests → docs
AI Coding Pair Claude Code and Codex by module responsibility while strictly enforcing server-only boundaries and repository conventions
Quality Control Human architecture & edge-case review + zero-warning lint + unit / integration / Playwright E2E suites + coverage gates — never weakening assertions
Security Control Least-privilege design, pre-push secret/internal-host leak checks (check-public-history.py), CodeQL analysis, and lockfile registry audits
Product Delivery Automated multi-platform packaging and multi-arch container builds, paired with synchronized bilingual docs, Wiki, and changelogs

Case Study: Whole-File Scanned PDF Import & Cross-Page Merging

In v2026.11.19 of wrong-notebook, a flagship feature — importing an entire scanned PDF as a single recognition batch, merging split questions across pages, and extracting answer-key pages automatically (38 files changed in one coordinated delivery) — went end-to-end through this workflow:

  1. Requirements & Guardrails: Eliminated manual page-by-page screenshotting for full exam PDFs, while enforcing an explicit constraint that AI outputs enter a batch review queue before database persistence and never break single-image uploads.
  2. Contracts & Context: Guided by AGENTS.md (BaseAIProvider contract, withUser auth guards, bilingual i18n parity), defined ImportBatch versioned server-side drafts (conditional draft -> started transition against duplicate runs), cross-page question-stitching rules, and answer-key mapping schemas first.
  3. Decomposition & Implementation: Split into PDF page-stream and region-cropping logic (scanned-pdf-flow.ts, batch-crop.ts), provider question-split extensions (question-split.ts), the batch review workspace (import-batches/[id]/page.tsx), and bilingual UI strings.
  4. Verification & Release: Shipped alongside 4 Vitest unit test suites (base-provider.test.ts, question-split.test.ts, scanned-pdf-flow.test.ts, file-import-scanned-pdf.test.tsx), API integration tests (import-batches.test.ts), and mock-AI Playwright E2E specs (file-import-pdf.spec.ts), then released across Docker, desktop, and NAS packages after human review and green CI.

Observability & Reliability · Production Recovery

Production systems earn trust not on happy-path demos, but when dependencies degrade, queues redeliver, and latency spikes:

  • Four-Signal Evidence Chain: Correlating business state (MySQL), time-series metrics (Prometheus), structured logs (Loki / ELK), and unified trace_ids — exposed to agents strictly via read-only MCP bridges for triage without write escalation.
  • Truthful Release Gates: Separating COMPLETED, DENIED (correct policy block), WAITING_APPROVAL, and FAILED outcomes so raw success-rate percentages never mask security bypasses or silent retries.
  • Backend Troubleshooting: P95/P99 latency analysis, retry storms, message backlogs, worker crash idempotency (leases, fencing tokens, outbox), lock-free MySQL online DDL, and JVM off-heap memory profiling with gperftools.

Engineering Principles

  • Reliability First: Define identity, permissions, timeout budgets, idempotency keys, circuit breakers, and rollback paths before scaling features.
  • Security & Least Privilege: Keep secrets out of repositories and logs, validate schemas strictly, default to read-only access, and bind high-risk approvals to canonical parameters.
  • Maintainability & Explicit Contracts: Prefer explicit state machines, versioned APIs, structured logs, and repository guardrails (AGENTS.md) over implicit conventions.
  • Evidence-based Engineering: Prove correctness — whether human-written or AI-assisted — with reproducible tests, coverage gates, observability signals, and postmortems rather than plausible output.
