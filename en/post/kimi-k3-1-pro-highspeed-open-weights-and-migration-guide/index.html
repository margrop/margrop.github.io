4. Root Cause: The 7 Breaking API Changes Between K2 and K3.1 Pro

Why do legacy K2 payloads fail or bust the cache on K3.1 Pro? Here is the complete seven-part root-cause diagnostic matrix:

Everyday Analogy 4: The “Locked F1 Gearbox” and “Sticky Notes on the Mathematician’s Desk”

To make the first four protocol rules unforgettable, think of two simple everyday objects:

  1. Root Causes 1 & 2 (Locked sampling parameters + Removed thinking dict = A Locked Formula 1 Gearbox): In the K2 era, the model behaved like an old manual-transmission sedan where you could tweak temperature=0.2 or pass thinking: {"type": "disabled"}. By contrast, kimi-k3.1-pro was trained end-to-end with Joint RL under a calibrated sampling distribution: temperature = 1.0, top_p = 0.95, n = 1, presence_penalty = 0, and frequency_penalty = 0. Forcing temperature = 0.2 collapses its multi-step exploration tree. To prevent silent accuracy degradation, Moonshot locked those parameters at the API gateway: passing any non-default sampling value or a legacy thinking dictionary immediately returns HTTP 400. The only valid knob for reasoning depth is the top-level reasoning_effort parameter ("low", "high", or "max", defaulting to "max").
  2. Root Causes 3 & 4 (Mandatory reasoning_content echo + Prefix cache invalidation on effort changes = Sticky Notes on a Mathematician’s Desk): K3.1 Pro uses always-on Preserved Thinking. Picture a mathematician solving a 20-step proof who writes intermediate deductions on yellow sticky notes (reasoning_content) before reaching for a reference book (calling a tool). If your multi-turn agent loop only appends content and tool_calls back into messages and strips reasoning_content, you are ripping every sticky note off the desk while the mathematician turns around — forcing the model to re-derive everything from scratch or hallucinate. Similarly, changing reasoning_effort mid-conversation alters the internal prompt prefix encoding, immediately invalidating your 1M token cache.
  3. Root Cause 5 (Remote HTTP Image URLs Rejected): K3.1 Pro’s vision endpoint does not fetch external https://... image links on your behalf and requires content to be an array of typed objects. Always encode local images as data:image/jpeg;base64,... or upload them via the Files API (ms://<file-id>).
  4. Root Cause 6 (Claude Code’s 5 Model Variables & settings.json Override): Exporting ANTHROPIC_MODEL in your shell is not enough. Claude Code routes subagents and background tasks through ANTHROPIC_DEFAULT_HAIKU_MODEL and CLAUDE_CODE_SUBAGENT_MODEL, and any existing ~/.claude/settings.json file silently overrides shell exports.
  5. Root Cause 7 (CN Trial Voucher Restriction & K2 Sunset Window): On the domestic China platform (platform.kimi.com), the complimentary 15 RMB new-user trial voucher cannot be used to call kimi-k3.1-pro (a top-up balance of at least 15 RMB unlocks access).
