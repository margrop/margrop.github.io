Problem Analysis & Root Cause: The Overseas Unfurnished Flat vs. The Turnkey Apartment

1. The Hidden Truth About Stock HAOS: You Only Flashed an Empty Shell

A universal misconception among beginners is assuming that the several-hundred-megabyte HAOS image contains the complete Home Assistant application. In reality, it does not. To keep the base OS image compact and version-independent, stock HAOS ships only a minimal Linux kernel, the container orchestrator (hassio_supervisor), and a tiny placeholder web server called landingpage. Think of it as an unfurnished concrete shell with a contractor standing inside.

The moment you plug in the power cord, the contractor (Supervisor) wakes up and tries to order all the actual furniture—beds, sofas, kitchen appliances (the multi-gigabyte homeassistant Core container and system plugins)—from overseas warehouses. During this first boot, it must clear four strict network checkpoints in sequence:

  • Checkpoint 1: NTP Clock Synchronization (The Silent Killer) Brand-new mini-PCs, ARM TV boxes without CMOS batteries, or freshly created virtual machines often boot with a skewed system clock. If the default overseas NTP servers time out, the system clock remains out of sync. Every subsequent HTTPS request immediately fails because TLS certificates appear “not yet valid” or expired.
  • Checkpoint 2: Version Manifest Resolution Supervisor queries version.home-assistant.io to discover the latest release tags. If DNS resolution or CDN routing stalls here, Supervisor does not even know which container version to pull.
  • Checkpoint 3: Multi-GB Container Layer Pulls from ghcr.io (90% of All Hangs) All official Home Assistant containers (core, cli, dns, audio, observer, multicast) live on GitHub Container Registry (ghcr.io). The Core image alone consists of 32 compressed layers totaling nearly 2 GB unpacked. Over a congested cross-border link, if even one layer suffers a TCP reset or stalls mid-stream, the pull aborts and restarts from scratch.
  • Checkpoint 4: Internal DoT / DNS Forwarding Deadlocks The built-in hassio_dns plugin defaults to DNS-over-TLS fallbacks that frequently clash with double-NAT optical modem topologies in home networks.

2. How Wintermelon HAOS Eliminates Every Bottleneck at the Root

Once you understand those four checkpoints, the engineering behind Wintermelon HAOS (wghaos) becomes crystal clear:

  1. Domestic High-Speed Registry (r.hassbus.com) + haos-turbo Engine: Under the hood, Wintermelon HAOS redirects container pulls from throttled overseas registries to dedicated domestic mirror clusters (such as r.hassbus.com) paired with the haos-turbo acceleration service. Instead of waiting hours for cross-border shipping, all 32 layers stream from a local warehouse at full broadband speed.
  2. Port 8124 Wintermelon Companion (Your Visual Concierge Lobby): Instead of staring at a vague spinner on port 8123, you open port 8124 immediately after boot. A clean graphical dashboard shows the exact initialization stage, which of the 7 core containers are running, how many image layers have finished downloading, and whether NTP time and network connectivity are healthy.
  3. Pre-Loaded HACS & 19 One-Click Self-Healing Tools: Out of the box, HACS and essential system add-ons are pre-configured. If you ever hit peak-hour congestion, forget your password, or encounter a Supervisor glitch, 19 red buttons in the Companion UI let you switch mirror nodes, sync NTP time, or repair Supervisor with a single click—zero command-line typing required.

Step-by-Step Part 1: Golden Virtual Machine & BIOS Parameters

Let us walk through creating the virtual machine in Proxmox VE (PVE)—the exact same principles apply to Synology Virtual Machine Manager, VMware Workstation, and bare-metal motherboard BIOS settings.

Before clicking through the wizard, let us demystify the two hardware switches that cause 95% of boot failures:

  1. Why MUST BIOS be set to OVMF (UEFI) instead of SeaBIOS? Think of legacy SeaBIOS (MBR) as an old-fashioned metal key, while Wintermelon HAOS uses a modern electronic smart-card lock (UEFI GPT partition table). If you leave the VM on default SeaBIOS, it tries to jam a metal key into an electronic reader—resulting in an immediate black screen stuck at Booting from Hard Disk….
  2. Why should CPU Type be set to host? Default virtual CPUs (such as kvm64 or qemu64) act like speaking through a slow interpreter, hiding modern encryption and vector instructions. Selecting host lets Wintermelon HAOS talk directly to your physical CPU cores, unlocking the full speed of the native x86-64-pc build and cutting container extraction time in half.

Deep Troubleshooting Q&A for Beginners

Q1: Why do both http://homeassistant.local:8124 and :8123 fail to open several minutes after power-on?

Check these three common culprits in order—99% of cases are resolved within one minute:

  1. Optical Modem vs. Secondary Wi-Fi Router Subnet Isolation (Most Common): Many homes have an ISP optical modem/router upstream and a personal Wi-Fi router downstream. If you plug the HAOS box into the optical modem while your laptop/phone is connected to the secondary Wi-Fi router, they sit on two separate subnets! Always connect your HAOS host, computer, and phone to the exact same router (and never plug into an ISP IPTV-dedicated port).
  2. Router Does Not Forward .local (mDNS) Broadcasts: Some routers block mDNS resolution across Wi-Fi and wired LAN ports. Log into your router’s admin page, check the DHCP client list for a device named homeassistant, and connect using its assigned local address plus :8124. (If you use an ARM box with a front LCD display, it cycles through status screens every 90 seconds—look for LAN IP rather than GATE IP).
  3. VM Network Adapter Set to NAT Instead of Bridged: In VMware Workstation or VirtualBox, verify that the virtual NIC is set to Bridged Mode so the VM receives a real LAN address from your home router.

Q2: Why does my VM freeze on Booting from Hard Disk... or boot right back into the blue WinPE desktop?

  • Frozen on Booting from Hard Disk... or No bootable device: Your VM firmware is still set to legacy SeaBIOS. Shut down the VM, switch BIOS to OVMF (UEFI) under the System tab (or enable UEFI boot in physical motherboard BIOS), and start it again.
  • Boots back into the WinPE desktop: You forgot to unplug the Ventoy USB drive or unmount the win10pe…iso file from the VM’s virtual CD/DVD drive after the installer finished.

Q3: What if initialization stalls at a specific layer during evening peak hours (18:00–20:00)?

Do not re-flash the disk! Instead, let Wintermelon Companion heal itself:

  1. Open http://homeassistant.local:8124/ and sign in at the top right;
  2. Open the 常规维护 (Routine Maintenance) tab on the left;
  3. Click 同步系统时间 (Sync System Time) first, then click 系统换源 (System Mirror Switch) to hop to an uncongested domestic mirror node;
  4. If the supervisor container is stuck restarting, click 修复Su启动故障 (Repair Supervisor) and reboot—initialization will resume cleanly.

Q4: I imported the raw .img.xz virtual disk directly instead of using the WinPE ISO. Why is disk space almost full?

To keep download sizes small, raw .img.xz images ship with a compact partition layout.

  • When you use the WinPE installer method covered in this guide, it writes onto your 32 GB virtual disk and automatically expands the data partition on first boot;
  • If you manually imported haos_x86-64-vm…img.xz into PVE, VMware, VirtualBox, or Hyper-V, use your hypervisor’s disk resize setting to enlarge the virtual disk to 32 GB or 64 GB, then reboot HAOS. The operating system detects the unallocated space during boot and automatically expands the Data partition without losing a single byte.

Q5: What happens if I forget my Home Assistant login password later on?

You never need to reinstall! While stock HAOS requires attaching a physical monitor and keyboard to run CLI auth resets, Wintermelon HAOS lets you open Port 8124 Companion, navigate to 常规维护 (Routine Maintenance) → 修改HA密码 (Change HA Password), and reset any local account password in seconds.

Q6: Any pitfalls to watch out for when setting a Static IP for Home Assistant?

Locking in a fixed local address prevents dashboard bookmarks from breaking after a router reboot. You can either bind a static DHCP lease on your router (recommended) or configure a static IPv4 address inside Home Assistant under Settings → System → Network.

[!WARNING] Critical Reminder Before Replacing Your Home Router: If you hardcode a static IPv4 address inside Home Assistant and later buy a new router that uses a different subnet, always switch Home Assistant back to Automatic (DHCP) before unplugging your old router! Otherwise, the box will cling to the old subnet and become unreachable on the new router. (If you ever get locked out this way, attach a monitor and keyboard, type net up end0 –ipv4-method auto at the prompt, and press Enter to restore DHCP).
