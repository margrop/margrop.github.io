1. Background: The Origin of the Hybrid and Its Seductive Promise

To understand why this model created both awe and frustration, we must first examine how it was constructed.

In traditional deep learning, an empirical law has long held sway: reasoning depth correlates with parameter volume, which in turn correlates with hardware expense. Frontier models like DeepSeek-V4-Pro feature 671 billion (671B) total parameters in a Mixture-of-Experts (MoE) configuration. While brilliant at symbolic math and multi-step deduction, running such giants unquantized demands multi-GPU server infrastructure far beyond the reach of standard workstations.

To democratize this capability, open-source researchers (such as community developer Jackrong and quantizer mradermacher) turned to advanced knowledge distillation and policy alignment.

Figure 2: Real browser screen capture of the Hugging Face repository. Over 48,000 downloads and near-70B performance scores across MATH-500 and AIME 2024 evaluations.

The architectural lineage consists of three components:

  1. The Teacher Model —— DeepSeek-V4-Pro (Max Effect Mode): DeepSeek’s 671B MoE engine was tasked with solving 250,000 rigorous STEM, competitive coding, and collegiate mathematics problems. It produced rich Chain-of-Thought (CoT) trajectories featuring multi-step hypotheses, self-reflections, and formal proofs.
  2. The Student Host —— Qwen3.5-9B Dense: Alibaba’s Qwen3.5-9B was chosen as the physical container due to its native Grouped-Query Attention (GQA), exceptional multi-lingual tokenizer, and 128k long-context scaling ceiling.
  3. The Distillation Recipe —— SFT + GSPO Reinforcement Learning: Supervised fine-tuning transferred the teacher’s problem-solving cadence, while Generalized Sequence Policy Optimization (GSPO) reinforced reasoning discipline and penalized redundant verbosity.

On paper, the model delivered a breakthrough: a 9B model that fits into 5.8 GB of VRAM under 4-bit quantization, running at nearly 50 tokens per second while challenging 70B models. However, when deployed naively, major friction surfaced.

2. Problem Symptoms: Four Critical Failures in Default Deployments

When running this raw hybrid checkpoint in default local runtimes (such as standard Ollama or basic llama-cli), users routinely encounter four severe failure modes:

1. Symptom 1: The Infinite Reasoning Loop

This is the most notorious roadblock.

When presented with a deductive question (such as finding the inradius of a right triangle or deriving an algorithmic recurrence relation), the model emits an opening <think> token and begins reasoning.

Instead of concluding after a brief period, the model becomes trapped in cyclical doubt. It calculates the correct answer, remarks “Wait, let me verify if this formula holds unconditionally”, recalculates via an alternate method, and then muses “Wait, what if there is an edge case? Let me re-read the prompt”. It cycles through this loop dozens of times.

Figure 4: Real terminal screen capture. An uncalibrated hybrid model trapped in an infinite <think> loop, exhausting the 2048 token buffer without delivering an answer.

Eventually, the model burns through its context limit with redundant hesitation. The session crashes or abruptly truncates, leaving the user with zero final output.

2. Symptom 2: Token Protocol Collision & Delimiter Leakage

The second breakdown occurs at the tokenization boundary.

Under normal conditions, control tokens remain hidden from the end user. With this hybrid, raw markers like <|im_start|>system, <|im_end|>, and <｜begin of sentence｜> frequently spill into the terminal.

Figure 5: Real terminal screen capture. Missing stop tokens allow the model to bypass conversational boundaries, leaking raw markup and simulating artificial user replies.

Because the inference engine fails to register the proper stop signal, the model does not brake after finishing its response. It fabricates a fictitious <|im_start|>user query and responds to itself as <|im_start|>assistant in an unprompted loop.

3. Symptom 3: Context Starvation and Amnesia

Many local LLM runners enforce conservative context allocations (often 2048 tokens by default) to accommodate legacy hardware.

For concise models, 2048 tokens is adequate. But for a model distilled with DeepSeek’s exhaustive CoT patterns, 2048 tokens barely covers initial scratchpad notes. Once the token ceiling is reached, earlier reasoning vanishes from memory, leading to severe hallucination and fractured deductions.

4. Symptom 4: Quantization Collapse from Uncalibrated Pruning

Users seeking minimal memory footprints often grab naive Q3 or uncalibrated Q4_0 quantizations. Unfortunately, standard uniform quantization rounds off the delicate attention weights responsible for reflection and error-checking, undermining the model’s deductive accuracy.

The core lesson is straightforward: the student inherited a giant’s thinking habits, but was denied the workspace required to finish them!

2. Analogy 2: Clashing Traffic Light Systems

The delimiter leakage issue represents a traffic signal miscommunication.

The base model Qwen natively adheres to the ChatML traffic system:

  • Green Light: <|im_start|>assistant indicates permission to drive and generate tokens;
  • Red Light: <|im_end|> commands an immediate full stop.

However, during distillation, the teacher model DeepSeek introduced its own protocol symbols: <think> opens reasoning, </think> concludes thinking, and <｜end of sentence｜> indicates final completion.

When deployed without an explicit translation wrapper (a tailored Modelfile), the local traffic controller only watches for standard ChatML stop signs. When the model emits DeepSeek’s termination token, the controller fails to recognize it and keeps the signal green. The model assumes the session remains open, fabricates new user questions, and continues generating output indefinitely.

4. Root Cause Analysis: Four Architectural Bottlenecks

Moving from analogies to system internals, four technical root causes explain these behaviors:

Figure 6: Original architecture diagram detailing the four-phase pipeline: teacher CoT generation, supervised fine-tuning, GSPO policy alignment, and edge imatrix quantization.

Root Cause 1: Misalignment Between ChatML and DeepSeek Control Tokens

In raw Hugging Face checkpoints, tokenizer_config.json blends Qwen’s ChatML definitions with DeepSeek special tokens. During conversion to GGUF format, explicit stop mappings are easily dropped. If the inference harness lacks hardcoded stop definitions for <|im_end|>, <|endoftext|>, and <|im_start|>, the autoregressive generation loop fails its End-of-Generation check.

Root Cause 2: RoPE Frequency Configuration and Token Starvation

Qwen3.5 natively supports up to 128k context windows via an elevated rope_theta of 1,000,000. Yet local runners default to 2048 tokens to conserve VRAM. In complex mathematical proofs, intermediate reasoning steps easily consume 1,500 to 3,000 tokens. Once the allocated KV cache is filled, earlier context is truncated, breaking deductive continuity.

Root Cause 3: Uncalibrated Sampling Parameters (Temperature and Top-P)

Setting temperature above 0.7 introduces high variance into reasoning chains. In self-reflection modes, probability noise encourages the model to branch into endless secondary questions. Conversely, setting temperature to absolute zero can trap greedy decoding in repetitive loops.

Root Cause 4: Weight Degradation from Naive Quantization

In a 9B model, key attention heads exhibit delicate activation patterns. Uniform 4-bit quantization (such as Q4_0) clips subtle attention weights. Preserving reasoning fidelity requires Importance Matrix (imatrix) quantization (e.g., Q4_K_M or IQ4_XS), which protects critical mathematical weights based on calibration data.

Resolving these issues requires four targeted adjustments:

1. Intervention 1: Craft a Custom Modelfile with Triple Stop Delimiters

Whether using Ollama or llama.cpp, you must supply an explicit prompt template that binds ChatML delimiters with DeepSeek thinking blocks, enforced by three stop rules:

2. Intervention 2: Expand Context to 16,384 Tokens

Explicitly set num_ctx 16384 (16k). Thanks to Qwen3.5’s native Grouped-Query Attention (GQA), a 16k context window under FP16 KV caching adds only ~1.2 GB of VRAM overhead. On memory-constrained devices, enabling q8_0 or q4_0 KV cache quantization provides ample headroom without sacrificing precision.

3. Intervention 3: Calibrate Sampling Parameters for Stable Convergence

Extensive testing across mathematics benchmarks yields an optimal hyperparameter profile:

  • Temperature = 0.6: Balances creative exploration with deductive stability;
  • Top-P = 0.95: Trims low-probability noise;
  • Repeat Penalty = 1.08: Discourages repetitive phrases, helping the model conclude reasoning cleanly.

# ==============================================================================
# Windows 11 Automated Deployment for DeepSeek-V4-Pro + Qwen3.5 9B Hybrid
# Filename: deploy_hybrid_win11.ps1
# ==============================================================================
param(
    [switch]$AgentMode = $false
)

$ErrorActionPreference = "Stop"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

function Write-Log {
    param([string]$Message, [string]$Level = "INFO")
    if (-not $AgentMode) {
        $color = switch ($Level) {
            "SUCCESS" { "Green" }
            "WARN"    { "Yellow" }
            "ERROR"   { "Red" }
            default   { "Cyan" }
        }
        Write-Host "[$Level] $Message" -ForegroundColor $color
    }
}

Write-Log "Initializing Windows 11 deployment pipeline..." "INFO"

# 1. Hardware Detection
$hasCuda = $false
try {
    $gpu = Get-CimInstance Win32_VideoController | Where-Object { $_.Name -like "*NVIDIA*" }
    if ($gpu) {
        $hasCuda = $true
        Write-Log "Detected NVIDIA GPU: $($gpu.Name)" "SUCCESS"
    } else {
        Write-Log "No dedicated GPU detected; configuring AVX-512 CPU acceleration" "WARN"
    }
} catch {
    Write-Log "Hardware scan bypassed; running in standard mode" "WARN"
}

# 2. Verify or Install Ollama
if (-not (Get-Command "ollama" -ErrorAction SilentlyContinue)) {
    Write-Log "Ollama not found. Installing silently via WinGet..." "INFO"
    winget install -e --id Ollama.Ollama --accept-source-agreements --accept-package-agreements --silent
    $env:Path = [System.Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("Path","User")
}

try {
    $null = Invoke-RestMethod -Uri "http://localhost:11434/api/tags" -Method Get -TimeoutSec 2
} catch {
    Write-Log "Starting background Ollama service..." "INFO"
    Start-Process "ollama" -ArgumentList "serve" -WindowStyle Hidden
    Start-Sleep -Seconds 3
}

# 3. Workspace Setup and Model Ingestion
$workDir = Join-Path $env:USERPROFILE ".hybrid_models\deepseek_qwen_9b"
if (-not (Test-Path $workDir)) { New-Item -ItemType Directory -Path $workDir -Force | Out-Null }

$ggufUrl = "https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/resolve/main/DeepSeek-V4-Pro-Qwen3.5-9B.Q4_K_M.gguf"
$ggufPath = Join-Path $workDir "DeepSeek-V4-Pro-Qwen3.5-9B.Q4_K_M.gguf"

if (-not (Test-Path $ggufPath)) {
    Write-Log "Downloading Q4_K_M weights (~5.8 GB)..." "INFO"
    curl.exe -L -C - --retry 5 --retry-delay 3 -o $ggufPath $ggufUrl
}

$modelfileContent = @"
FROM $ggufPath

TEMPLATE """{{ if .System }}<|im_start|>system
{{ .System }}<|im_end|>
{{ end }}{{ if .Prompt }}<|im_start|>user
{{ .Prompt }}<|im_end|>
{{ end }}<|im_start|>assistant
{{ .Response }}<|im_end|>"""

PARAMETER stop "<|im_end|>"
PARAMETER stop "<|endoftext|>"
PARAMETER stop "<|im_start|>"
PARAMETER num_ctx 16384
PARAMETER temperature 0.6
PARAMETER top_p 0.95
PARAMETER repeat_penalty 1.08
"@

$modelfilePath = Join-Path $workDir "Modelfile"
[System.IO.File]::WriteAllText($modelfilePath, $modelfileContent, [System.Text.Encoding]::UTF8)

# 4. Compile Model Instance
Write-Log "Compiling and registering 'deepseek-v4-qwen35-9b'..." "INFO"
& ollama create deepseek-v4-qwen35-9b -f $modelfilePath | Out-Null

# 5. Smoke Test
$testPrompt = @{
    model = "deepseek-v4-qwen35-9b"
    prompt = "Which number is larger: 9.11 or 9.9? Answer in one sentence."
    stream = $false
} | ConvertTo-Json

$testRes = Invoke-RestMethod -Uri "http://localhost:11434/api/generate" -Method Post -Body $testPrompt -ContentType "application/json"

if ($AgentMode) {
    @{
        status = "success"
        platform = "Windows 11"
        model = "deepseek-v4-qwen35-9b:latest"
        vram_optimized = $hasCuda
        context_window = 16384
        endpoint = "http://localhost:11434"
        smoke_test_response = $testRes.response.Trim()
    } | ConvertTo-Json -Compress
} else {
    Write-Log "Deployment completed successfully!" "SUCCESS"
    Write-Log "Smoke Test Output: $($testRes.response.Trim())" "SUCCESS"
    Write-Log "You can now run: ollama run deepseek-v4-qwen35-9b" "INFO"
}

8. Community Q&A: Addressing Core Technical Doubts

Q1: Can a 9B hybrid truly replace 70B or 671B frontier models across the board?

Answer: No, and it should not be treated as a universal drop-in replacement.

Distillation transfers reasoning discipline and deductive structure; it does not expand total factual capacity. For well-defined STEM challenges, mathematical olympiad problems, code synthesis, and structured workflows, the 9B model rivals 70B counterparts.

However, tasks requiring massive factual knowledge (such as obscure legal statutes or historical trivia) remain constrained by the 9B parameter envelope. It excels as an accurate, dedicated mathematical and algorithmic assistant, not an all-knowing encyclopedia.

Q2: Why does perceived generation feel slower than vanilla Qwen2.5/3.5-9B?

Answer: Thorough reflection requires generating physical tokens.

Conventional chat models output answers immediately. Reasoning models must first generate tokens across the <think> phase. Even running at 50 tokens per second, producing a 400-token proof requires roughly eight seconds before the visible answer appears. The perceived pause represents computation spent eliminating logical errors.

Q3: Can I run this model on a thin-and-light laptop lacking a dedicated GPU?

Answer: Yes, smoothly.
