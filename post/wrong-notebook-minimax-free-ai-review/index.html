不用先配 API Key：支持飞牛OS的 AI 错题本，接上了 MiniMax 免费账号

发布时间: 2026-10-25 · 阅读量 --
AI 教育 Education 学习 Learning 开源项目 Open Source 自托管 Self-hosting

给孩子用 AI 错题本，有一道门槛往往出现在第一道题之前：软件装好了，AI 要怎么接？

API Key、接口地址、模型名称，熟悉的人几分钟就能填完；对只想拍一道数学题、看看错在哪里的家长来说，却像去图书馆借书，先被要求研究借阅系统怎么联网。

最近，我给自家孩子持续使用和迭代的 wrong-notebook，把这道门槛往下放了一点：新增 MiniMax Code OAuth，可以通过网页登录 MiniMax Code 账号，使用账号里的免费积分调用 AI，不必先准备开放平台 API Key。默认模型是 MiniMax-M3.1-Flash。

这次也补上了几件更贴近日常的小事：今天该复习哪些题，昨天没做完的变式题能不能接着做，答案少写一位会不会被误判为正确，换设备时练习记录会不会丢。

图 1：本文原创配图。免费积分来自平台，复习安排来自应用，两者各管一件事。

本文核对的是 2026 年 10 月 25 日公开正式版 v2026.10.25。项目 fork 自 wttwins/wrong-notebook，感谢上游提供基础。我在自己的分支上围绕家庭使用补功能、修问题；它已经在使用，也会继续随着实际问题迭代。

免费账号接进来了，先分清楚选哪个渠道

设置里的两个名字很像，但接的是两套不同的入口。

渠道 怎样连接 使用哪边的额度
MiniMax 填开放平台 API Key 开放平台对应账户和接口的额度、余额与计费规则
MiniMax Code OAuth 在官方网页完成账号授权 MiniMax Code 账号可用积分，包含平台提供的免费积分

API Key 本身是一种访问凭证，并不是“买到手的一张模型”。这次省掉的，是先到开放平台准备凭证、再把接口参数搬进应用的步骤。免费账号走的是 MiniMax Code OAuth，不能把它和原来的 MiniMax API Key 配置混为一谈。

图 2：当前版本真实设置界面，使用独立演示环境，保留未登录状态；这里展示入口，不展示或编造真实积分余额。

管理员进入“设置 → AI 设置”，选择 MiniMax Code OAuth，点击“网页登录”，在打开的 MiniMax 页面完成登录与授权。如果浏览器拦住了新窗口，设置页也提供打开授权页面的链接。完成后回到应用，保存渠道和模型配置，再使用连接测试核对当前账号是否可用。

可以把 OAuth 理解成图书馆发的一张借阅许可。账号密码在 MiniMax 的登录页面处理，应用拿到授权后的凭据，凭许可去调用服务。正常使用不需要家长手工复制一长串 Token。登录失效时重新授权，访问凭据临近到期时应用会尝试自动续期。

项目发布说明记录，免费账号已可使用默认的 MiniMax-M3.1-Flash，并支持图片识别。识题、解析、举一反三和判题都接在现有的学习流程里，不需要先把题目复制到另一个聊天窗口，再把结果搬回来。模型是否对某个账号开放，仍以该账号实际权限和调用结果为准。

免费积分，是可用的学习预算

“支持免费账号”容易被听成“所有功能永远不限量”。这里需要把账说清楚。

免费积分由 MiniMax Code 提供，wrong-notebook 负责连接账号、显示余额和发起请求。平台可能调整赠送方式、签到奖励、积分有效期、模型权限或限流规则。本文不写一个没有可靠依据的“每天固定送多少”，也不把积分换算成固定能识别多少道题。

图 3：两个入口像两张不同用途的卡。账户都属于同一家服务，也不代表余额能直接互用。

设置页会分别展示总剩余积分、免费积分和购买积分。若账号同时持有购买积分，应用并没有提供一个“只扣免费部分”的独立消费开关；实际扣减顺序和费用归属由平台规则决定。网络暂时查不到余额时，应先看查询状态，不能把“暂时不可用”当成已经没有积分。

这更像给孩子准备了一袋游乐园的体验券：券能让人先玩起来，但每个项目消耗不一样，园方也可能调整活动。比较实用的做法，是先拿一道没有隐私的普通题试用，确认识别、解答和实际积分变化，再决定怎样安排后续使用。

还要区分授权方式与服务承诺。当前渠道沿用 MiniMax Code 客户端的设备码授权方式，调用其客户端相关接口，并不是 MiniMax 开放平台对第三方错题本提供的长期公开 API 合同。请遵守平台服务条款；上游调整时，该渠道也可能需要跟进。

自动签到：让常开设备记住这件小事

积分能领到，却总忘记领取，也是一个容易打断使用的小环节。这次增加了每日自动签到，默认开启，并在设置页展示今天的签到结果。

它的运行方式比较朴素：服务启动约一分钟后做第一次检查，随后每小时检查一次。如果账号已登录、开启自动签到，而且按北京时间判断今天尚未成功签到，就尝试领取。今天已经领过时只记录状态；失败会留在界面上，后续检查再尝试，也可以手动点击立即签到。

图 4：签到依赖实际运行的服务进程，日期按 Asia/Shanghai 判断；具体奖励以平台返回为准。

这像把“记得给绿植浇水”交给一个定时提醒器。提醒器得开着电，才能到时间查看。应用装在持续运行的飞牛OS或其他 NAS、Docker 服务上，比较容易维持这个条件；电脑关机、桌面程序退出、安卓单机版的服务被系统停止时，就不能指望它仍在后台领取。

更换应用显示时区，也不会把 MiniMax 的签到日改成另一个时区。平台按自己的日历结算，应用按自己的学习日历展示统计，两本日历需要分别理解。

把额度管好，比盯着余额更省心

接入门槛降低以后，还得避免同一道题被连续点十几次“重新生成”。新版增加“每人每日 AI 次数”，管理员可以在用户管理中设置，并查看每位用户今天的使用量。

图 5：真实管理界面。图中的上限和用量来自虚构演示数据，不是 MiniMax 免费账号承诺的每日额度。

这相当于家长在体验券之外，再给每个孩子约定“今天可以请求几次帮助”。它管的是应用里的使用节奏，和平台积分是两回事。

目前，0 表示不限制，也是默认值；限制针对普通用户，管理员不受限制，但仍记录用量。次数按应用时区的自然日统计。识题、重新解答、出题、AI 判题、动画和组卷等主动操作会计入；整套组卷可能在内部调用多次模型，却仍按一次组卷操作计数。后台自动进行的掌握概率评估不计入这个次数。

因此，“还有几次”和“还有多少积分”不能一一换算。请求发起前就可能记一次，失败操作也可能占用次数；统计异常时当前实现优先保留正常调用能力。这个功能适合家庭用量管理，不能据此保证平台账单存在一个绝对金额上限。

同一实例的 AI 配置由管理员管理。多个孩子有各自的学习数据和应用内用量记录，但通过这个配置使用的 MiniMax 积分仍来自同一个已授权账号。让孩子使用普通账户，通常比每个人都拿管理员账户更合适。新安装的注册入口默认关闭，需要为家人开户时再由管理员开启。

今天该翻哪几页，终于不用全靠家长记

便宜地生成很多解析，不等于错题就能发挥作用。我更关心的后半程，是过几天以后还能不能找到值得重做的那几道题。

上一篇介绍中，什么时候再次复习还主要由家长安排。这次新增了“今日复习”：首页显示今天待复习的数量，进入复习页，可以看到今天到期以及之前已经到期的题目，较早到期的排在前面。

图 6：当前首页实拍，题目和待复习数量均为演示数据。

图 7：当前复习页实拍。列表把“今天该看什么”放在一起，便于直接进入练习。

当前规则使用 1、2、4、7、15、30 天六档间隔。没有作答时从录入日安排；之后依据最近一次作答和末尾连续答对的次数推导下一次日期。做对进入下一档，做错回到第一档，标记“未作答”不会推动计划。连续完成六档后，不再给这道题安排这一轮的到期日期。

这些数字是本应用的预设规则，不能当作给所有孩子测定出的最佳记忆曲线，也不代表安装以后必然提分。

图 8：间隔指相邻阶段之间的天数，不是从第一天累计出来的第几天。实际日期按应用时区和作答记录计算。

可以把它想成老师在作业本上夹了六张书签：先隔近一点翻回来，连续做好后，再隔远一点。又做错了，就把书签放回前面，早点再看。书签帮忙提醒，不替孩子完成练习。

“今日复习”和“待复习、复习中、已掌握”三种状态也不是同一张标签。前者回答今天是否到期，后者根据练习记录和掌握概率做分类。达到 50% 分类阈值的题目，仍可能在某天需要回看；看到“已掌握”也不意味着能永久从学习中毕业。

昨天的练习，今天接着做

以前如果离开练习页，再回来时重新生成一道变式题，既多一次等待，也容易把本来准备做的题换掉。

现在，每道错题会暂存最近一次生成的举一反三题目、答案和解析，重新进入时直接显示。想换题时，再主动生成新的。它像在作业本里夹一张“做到这里”的便签，离开书桌回来以后，不必把整页重新抄一遍。

图 9：真实练习界面，暂存题目为手工准备的演示内容，说明页面恢复行为；没有借此截图声称刚完成了一次真实模型调用。

还有一个比省次数更重要的修复：判题终于不再因为“答案里包含你填的字”就轻易给绿灯。

旧逻辑里，标准答案是 120，学生填 12，可能因为子串包含而被判对。生活里这就像快递员看到门牌“120”包含“12”，就把包裹送进 12 号门；字符看起来挨着，含义却已经变了。

新版先做严格的本地比对：只在规范化后的答案一致，或可明确核对的选择题选项一致时直接确认正确。不能本地确认的，再交给 AI 对照服务端保存的题目与答案判断，并显示依据。AI 调用失败时留给人确认，不把失败偷偷变成“答对”。

图 10：本地没有确认一致，不等于已经判错。例如等价分数和不同解法，需要更完整的判断。

这个变化兼顾了两件事：容易确认的答案不用每次找模型，真正需要理解的答案也不会只靠字符串猜测。不过，AI 判断依然可能出错，题目识别有误、标准答案本身有问题时，更要回到原题核对。

图 11：真实详情页，使用演示作答历史。一次练习留下的记录，也会参与后续的复习安排。

放在飞牛OS上，或者放进自己的设备

wrong-notebook 仍然提供多种运行方式。家里已经有飞牛OS的读者，可以把它作为家庭学习资料的一项常驻服务；没有 NAS，也有其他入口。

方式 适合怎样使用
飞牛OS 使用对应安装包，在家庭 NAS 上运行，手机和平板访问同一服务
Docker 在支持的服务器或 NAS 上部署，支持 amd64、arm64 镜像
Windows、macOS、Linux 桌面版 希望在自己的电脑上运行，按需打开应用
npm / 源码运行 愿意自己管理 Node.js 和服务进程的用户
安卓单机版 设备内置服务端与本地数据，无须先另部署服务器
安卓客户端、浏览器与 PWA 连接已有服务；PWA 提供安装到主屏幕的入口

图 12：运行方式示意，不是真机安装测试截图。下载与设备要求以 安装包文档和对应 Release 资产为准。

这里可以用“厨房”来理解：飞牛OS、Docker 等服务端方式，像家里有一个大家共用的厨房；安卓客户端和浏览器是去这个厨房取餐；安卓单机版则把小厨房一起带在设备里。厨房在哪，题目和记录通常就保存在哪个实例里。调用外部 AI 时，相关题目和提示仍需要发到配置的服务，单机运行也不意味着 AI 可以断网使用。

本次源码运行的默认环境已升级到 Node.js 24，桌面和依赖也有更新。不过，日常读者无需为了读这篇文章先研究构建工具，直接按项目文档选择合适的安装包即可。

换设备时，别只搬走题干

这次的数据导入导出也更完整了。第 2 版备份除了错题本和错题，还覆盖练习、试卷、试卷题目及其作答记录、个人偏好，并补齐 GeoGebra、SVG 动画、最近暂存练习和掌握相关信息。

图 13：真实数据管理界面。网页导出的学习数据，和整站备份是不同范围。

像搬家一样，题干只是书，作答历史是夹在书里的批注，个人偏好是书架怎么摆。只搬走书，复习的来龙去脉可能就丢了。新版希望把这些学习资料一起带走。

但网页 JSON 备份不包含完整账户凭据、AI 配置或 MiniMax Code 登录凭据。换一套新实例以后，需要重新准备相关配置和授权；要做整站恢复，还应另行保存数据库、服务端配置及部署信息。安卓单机版卸载前尤其要先导出，不能指望系统自动备份替你保住所有资料。具体范围见数据备份与恢复。

几个可能会直接问到的问题

免费账号每天到底能用多少？

看账号当时的实际积分、平台规则和具体操作消耗。文章没有一个能对所有账号负责的固定数字。设置里看余额，先做小范围试用，比按别人的一次截图估算整个月更靠谱。

我已经用付费 API，还需要切换吗？

可以继续使用原来的渠道。新入口多了一种选择，不要求迁移现有配置。希望使用明确的开放平台计费与服务能力时，仍可按相应官方 API 方式连接。

自动签到是不是安装后就永远不用管？

需要服务保持运行、登录有效、网络可用，也受平台接口变化影响。设置页的今天状态才是这次是否成功的依据。家用 NAS 常开，通常更容易维持运行条件。

今日复习会替孩子制定个性化学习计划吗？

当前是依据记录执行六档间隔规则，不是测量孩子记忆能力后训练出的个性化算法。家长仍可结合课堂进度、孩子状态和实际错因安排额外练习。

AI 能替家长和老师做最终判断吗？

它能减少识别、整理、解释和出题的杂活，但题目条件、推理过程、单位和答案都值得核对。免费额度降低了尝试成本，没有取消检查的必要。

如果它也能帮你省下一点整理时间

我希望这轮更新带来的，是一条更容易坚持的家庭学习路径：用已有账号把 AI 接上，记住一道错题，留下一次真实作答，再在该回看的时候找到它。
