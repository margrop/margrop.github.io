查 IP 只会用百度？这个「网络体检中心」用 1600 个探针把你家网络扒得明明白白

发布时间: 2026-08-17 · 阅读量 --
ip IPv4 ipv6 network 公网IP 效率工具 网站推荐 network-toolkit

先问一个暴露年龄的问题：你想查自己 IP 的时候，第一反应是不是打开百度，搜「IP」？

如果你还停留在这个阶段，那今天这篇文章可能会刷新你的认知。查 IP 这件事，其实就像体检——量个血压（查个出口 IP）只是最基础的项目，真正的高手会连心电图、血常规、B 超一起做。而 ip.skk.moe 就是这样一个「网络体检中心」：免费、无广告、纯浏览器运行，一口气提供七项检查，从「我是谁」一路查到「我的 DNS 从哪个城市出门」。

我自己折腾软路由和分流规则好几年，每次排查「为什么这个网站慢」「分流到底生效没有」，最后打开的几乎都是它。这篇文章就带你把这个宝藏网站从头到尾盘一遍。

1. 它是什么：一个 2019 年活到现在的小众工具站

ip.skk.moe 是开发者 Sukka 在 2019 年建立的个人项目。Sukka 这个网名你可能不熟，但玩 Surge / Clash 分流规则的人几乎一定用过他维护的 ruleset 规则组——这个人在网络分流领域是实打实的「扫地僧」。

按照作者自己在 2023 年总结 里的说法，这个站最初只是一个简单的查 IP 页面，2023 年用 Next.js + React 18 重写之后，陆续加上了多出口分流查询、多数据源 GeoIP 查询、UDP 出口查询、域名分流测试等一系列「硬核玩家才懂」的功能。到了 2024 年，又加了 Zenlayer、Melbicom 等 CDN 的命中节点查询。

目前网站提供七个工具：

  1. 本机 IP 查询：看你的 IPv4/IPv6、地理位置、ISP、ASN。
  2. 网站分流测试：测试国内/国际网站分别走哪条出口。
  3. 多出口 IP 查询：用 1600+ 个探针验证你的策略路由。
  4. CDN 命中节点：看你被各家 CDN 分到了哪个边缘节点。
  5. DNS 出口查询：看你的递归 DNS 从哪个城市「出门」。
  6. WebRTC UDP 查询：检测 UDP 流量走哪个 IP 出口。
  7. IP 洞察：让一个 IP 同时接受 20 多个 GeoIP 数据库「会诊」。

2. 先把比喻讲清楚：IP、CDN、DNS 到底是什么

在深入每个功能之前，先用小学生都能听懂的话，把几个概念讲明白。后面所有内容都建立在这几个比喻上：

  • IP 地址 = 你家的门牌号。快递（数据包）要送到你家，得先知道门牌号。你上网时，网站看到的就是你的门牌号。
  • 出口 IP = 小区大门的出门登记。你家住几零几别人不关心，快递员只记录「这单是从哪个小区门出来的」。你和邻居可能共用同一个出口。
  • CDN = 开遍全国的快递柜。大网站不会只在一个地方放服务器，而是在全国、全球放很多「快递柜」（边缘节点），让你就近取件，速度才快。
  • DNS = 问路处。你想去「淘宝网」，先得问问路处「淘宝在哪」。问路处告诉你一个地址，你才能出发。
  • DNS 出口 = 问路处本人站的位置。关键来了：快递柜公司会根据「问路处站在哪」来决定让你去哪个柜子。如果问路处站在上海，哪怕你人在北京，也可能被分去上海的柜子——这就是很多人「明明有 CDN 却还是慢」的根源。

记住这五个比喻，下面的内容你就已经懂了一大半。

3. 本机 IP 查询：四个数据源交叉验证

首页就是最基础的功能，但做得比普通查 IP 网站讲究得多：

  • 左侧直接给出 IPv4 和 IPv6 的位置、ISP、ASN（自治系统号，可以理解为「运营商的身份证号」）。
  • 右侧同时调用 iP138、IP.cn、Cloudflare、IPinfo.io 四个数据源，国内国外各两个，交叉验证。
  • 下方还有一组「连通性测试」：字节跳动、Bilibili、微信、淘宝（国内）和 GitHub、jsDelivr、Cloudflare、YouTube（国际），实时显示延迟。

这个布局的实用之处在于：一眼就能看出你的网络处于什么状态。比如国内四个全绿、国际四个全红，说明你的国际出口挂了；反之亦然。而且页面右上角还有「隐藏 IP / 隐藏国内信息 / 隐藏国际信息」三个开关——截图发群里求助时不用再手动打码，这个细节真的很懂用户。

顺带一提：这个网站本身部署在 Cloudflare 后面，并且有比较严格的 WAF 防护。我用无头浏览器截图时就被拦了一次，返回了一个 403 安全拦截页。自己访问正常，但如果你写脚本批量调它，大概率会吃闭门羹。

4. 网站分流测试与多出口查询：软路由玩家的「照妖镜」

接下来是两个进阶功能，也是这个站和「百度查 IP」拉开差距的地方。

4.1 网站分流测试

配置了分流规则（国内直连、国外走节点）之后，怎么验证规则真的生效了？这个工具会同时访问一批国内和国际网站，告诉你每个网站是从哪个出口出去的。

打个比方：你家装了两个水表，一个接自来水，一个接净水器。分流测试就是挨个打开家里的水龙头，看看每个龙头流出的到底是哪种水。

4.2 多出口策略路由 IP 查询

这个更狠：它会通过 1624 个来自不同国家和地区的探针（基于 speedtest.net 的测速节点），逐个请求你的网络，看每个探针「眼中」你的出口 IP 是什么。

什么场景用得上？举个例子：你配置了 Split Tunnel（分流隧道），希望只有特定流量走隧道，其他流量直连。配置完心里没底？跑一遍多出口查询，如果所有探针看到的都是同一个 IP，说明你的分流根本没生效——流量全走了一个门。

这就像你为了上班不堵车，特意研究了「不同目的地走不同出口」的路线表。多出口查询就是派 1624 个人站在城市的每个出口等你，看你最终从哪个门出来。路线表写没写对，一测便知。

5. CDN 命中节点：你的快递柜到底分在哪

这是我个人最喜欢的一个页面。它会告诉你：访问 Cloudflare、Cloudflare 中国网络、Fastly、jsDelivr、AWS CloudFront、GCP、Akamai、Bunny、CDN77、腾讯 EdgeOne、Zenlayer、网宿等 20 多家 CDN 时，你分别被分配到了哪个边缘节点。

节点代号其实就是机场代码：SJC 是圣何塞、NRT 是东京成田、LAX 是洛杉矶、HKG 是香港。如果你人在国内，访问 Cloudflare 却命中 SJC（美国西海岸），那就解释了为什么你访问某些网站慢得像拨号上网。

用快递柜的比喻：这个页面就是把你常去的 20 家快递柜全部列出来，告诉你每一家分别把包裹放在了哪个城市。离得近的柜子当然取件快，被分到地球另一边的柜子，再宽的带宽也救不回来。

6. DNS 出口查询：找到「被带偏」的元凶

前面说过，CDN 按「问路处的位置」给你分柜子。那怎么知道你的问路处站在哪？DNS 出口查询就是干这个的：它通过多个检测服务（netease、ipleaks、browserleaks、surfshark、alibaba 等），查出你的递归 DNS 的出口 IP 及其地理位置。

举个真实场景：你人在北京，宽带是北京联通，但你的 DNS 设成了某个公共 DNS，它的出口在上海。于是 CDN 认为「这人在上海」，把你分到了上海节点。结果就是：北京到上海 1200 公里的物理距离，延迟天然多 20ms 起步，下载速度直接腰斩。

这就是 DNS 出口查询的价值——它能把「CDN 为什么把我带偏」这件事，从玄学变成可验证的事实。作者还贴心地附了一篇长文《是什么，为什么，怎么做——谈谈 DNS 泄漏、CDN 访问优化与 Fake IP》，想深挖原理的可以顺着读。

7. WebRTC UDP 查询：容易被忽略的一条「暗道」

大多数人测出口只关心 TCP（网页浏览走的协议），但现在语音通话、视频会议、QUIC/HTTP3 全走 UDP。WebRTC 默认使用 UDP，这个页面通过一系列 STUN 服务器（小米、腾讯、斗鱼、Google、Mullvad、Twilio 等），检测你发送 UDP 流量时使用的 IP 地址。

为什么重要？因为很多隧道工具只接管 TCP，UDP 悄悄从本地出口溜出去了——你以为自己藏好了，其实语音流量一直在「裸奔」。用比喻说：你给家门装了门禁（TCP 管控），却忘了厨房还有一扇小窗（UDP）没关。这个工具就是帮你检查那扇小窗的。

我的测试里只有 Google 的 STUN 成功返回了出口信息，其他大多超时——这本身也是有效信息，说明我的网络对大部分 STUN 服务器做了限制。

8. IP 洞察：20 多个数据库的「多方会诊」

最后一个工具适合「考古」用：输入任意一个 IP，它会同时向 IP.SB、IPQuery.io、GeoJS、IP-API、IPinfo、DB-IP、GeoLite2、IPIP.net、IP2Location、ipwhois、IPLocate、纯真 CZ88 等 20 多个 GeoIP 数据库发起查询，把结果列成一张大表。

这就像看病时的「专家会诊」：一个医生（数据库）可能误诊，但 20 个医生一起看，结论就靠谱多了。实际用途很多：排查某个 IP 到底是机房还是住宅、验证你自己的 IP 库标注是否准确、或者单纯研究各家 GeoIP 数据库的差异——你会发现同一个 IP，不同数据库给出的城市甚至国家都可能不一样，这正是 GeoIP 技术「仅供参考」的本质。

9. Q&A：你可能想问的几个问题

Q1：这个网站安全吗？会不会记录我的 IP？ A：你访问任何网站，对方都能看到你的 IP，这是互联网的工作原理，不是这个站特有的问题。它是知名开发者的个人项目，界面无广告、无追踪脚本泛滥的迹象。实在介意，可以用它首页自带的「隐藏 IP」开关。

Q2：和 ip138、ip.cn 比，优势在哪？ A：传统查 IP 网站只回答「我是谁」，这个站回答「我是谁、我从哪条路出门、我的 DNS 站在哪、CDN 把我分到哪、UDP 有没有漏」。一个是体温计，一个是体检中心。

Q3：普通人用得上吗，还是只有折腾党才需要？ A：普通人用「本机 IP 查询 + CDN 命中节点」就够了。比如你总觉得某个网站慢，打开 CDN 命中节点看一眼，发现被分到了海外节点，重启一下光猫换个出口 IP，往往立刻改善。

Q4：手机能用吗？ A：可以，响应式设计做得不错，本文好几张截图就是按移动端宽度截的。

Q5：为什么我的 STUN 测试大部分超时？ A：很多运营商和企业网络会限制 UDP 3478/19302 等端口，超时不代表你的网络坏了。只要有一两个 STUN 服务器能返回结果，就足够判断 UDP 出口了。

Q6：多出口查询要跑多久？ A：1624 个探针全跑完需要几分钟，但它是边跑边显示结果的，跑个一两百个通常就能看出分流是否生效了。
